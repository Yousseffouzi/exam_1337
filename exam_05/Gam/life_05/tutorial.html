What Is the Game of Life?

The Game of Life is a simulation invented by John Conway. It is called a game, but there is no player moving pieces after the start. You choose the first pattern, then the rules decide what happens next.

The world is a grid

Every square on the board is a cell. A cell has only two possible states:

  • Alive: printed as O in this subject.
  • Dead: printed as a blank space.
Alive Dead

Time moves in generations

One iteration creates one new generation. During each generation, every cell looks at its eight neighbors and decides whether it will be alive or dead in the next board.

123 4?5 678

The center cell checks the eight surrounding cells, never itself.

The 42 life Subject

Your program receives the board size and the number of simulation iterations as command-line arguments. The initial living cells are not typed as a grid; they are drawn by commands received from standard input.

Program shape

./life width height iterations

  • width is the number of columns.
  • height is the number of rows.
  • iterations is how many generations to simulate.

What happens in order

  1. Create an empty board.
  2. Read drawing commands until end of file.
  3. Use those commands to mark initial live cells.
  4. Run the Game of Life rules for the requested iterations.
  5. Print the final board.
Each cell outside the board is considered dead. That means border cells simply have fewer possible live neighbors.

Board, Cells, and Coordinates

Think of the board as rows and columns. The top-left cell is the starting point for the drawing pen. Moving right changes the column. Moving down changes the row.

A 5 by 4 board

0,0

The pen starts at the top-left corner before reading stdin.

Printing rule

The final output is a rectangle with exactly the requested width and height.

O O O OOO

Alive cells appear as O. Dead cells are spaces, so they are easy to miss without tools like cat -e.

Drawing the Initial Board with the Pen

Before the simulation starts, stdin describes a pen path. The pen always has a position, and it also has a drawing state: lifted or lowered. When lowered, the current cell becomes alive.

wMove up
aMove left
sMove down
dMove right
xToggle draw mode

Example command: dxss

  1. Start at top-left with the pen lifted.
  2. d: move right one cell.
  3. x: lower the pen and draw at the current cell.
  4. s: move down while drawing.
  5. s: move down while drawing again.

The drawn result

O O O

With zero iterations, this is exactly what gets printed.

Pen movement builds the initial picture only. After end of file, the pen is gone, and only the Game of Life simulation remains.

The Four Rules, One by One

For every cell, count how many of its eight neighbors are alive in the current board. Then apply exactly one rule to decide the cell's next state.

1. Underpopulation

Live cell with fewer than 2 live neighbors dies.

1 O
Next: dead

2. Survival

Live cell with 2 or 3 live neighbors stays alive.

12 O
Next: alive

3. Overpopulation

Live cell with more than 3 live neighbors dies.

12 3O4
Next: dead

4. Reproduction

Dead cell with exactly 3 live neighbors becomes alive.

12 3
Next: alive

Why You Need a Separate Next Board

In one generation, all cells must be judged from the same old board. If you change cells immediately while scanning, later cells will see mixed old and new information.

Helpful Patterns to Recognize

These patterns are not special cases in your program. They are useful because they help you test whether the rules are being applied correctly.

Block: stable

OO OO

Each live cell has exactly 3 live neighbors, so the block stays the same.

Blinker: oscillator

O O O

It flips between vertical and horizontal every iteration.

Edge behavior

OO O

There is no wrapping. Cells beyond the border are dead.

Complete Algorithm Steps, No Code

This is the full implementation path in plain language. Follow it in order and the exercise becomes much less mysterious.

1

Read and understand the arguments

Get the width, height, and number of iterations. These values define the board size and how long the simulation runs.

2

Create an empty board

Every cell starts dead. The board must have exactly height rows and width columns.

3

Initialize the pen

Place the pen at the top-left cell. Start with drawing turned off.

4

Read stdin until end of file

For each character, move the pen or toggle drawing mode. When drawing is on, mark the pen's current in-board cell as alive.

5

Repeat the simulation

For each iteration, create a fresh next board. Visit every cell, count its live neighbors from the current board, apply the four rules, and store the result in the next board.

6

Replace the board after each generation

Only after every cell has been decided should the next board become the current board.

7

Print the final board

Print O for alive cells and a space for dead cells. End every row with a newline.

Common Mistakes

Simulation mistakes

  • Updating the board in place during an iteration.
  • Counting the center cell as its own neighbor.
  • Wrapping around the board edges by accident.
  • Using the next board as input before the generation is finished.

Subject mistakes

  • Forgetting that the pen starts at the top-left corner.
  • Confusing movement commands with Game of Life movement.
  • Printing visible characters for dead cells instead of spaces.
  • Missing the newline after each output row.
The most important mental split is this: stdin drawing commands create generation 0; the Game of Life rules create generation 1, generation 2, and so on.

Quick Mental Checklist Before Implementing

Can you explain what a live neighbor is?
Can you draw the initial board from pen commands?
Can you apply the four rules without changing the old board?
Can you handle top, bottom, left, and right borders as dead outside?
Can you print spaces for dead cells and O for live cells?
Can you predict why dxss turns from vertical to horizontal after one iteration?
